# YTB2BILI 技术实现报告

## 项目概述

YTB2BILI 是一个功能完整的 YouTube 到 Bilibili 自动化视频转载系统。系统采用 Go 语言后端 + Next.js 前端的架构，支持从 YouTube 等平台下载视频，自动生成字幕、翻译内容、生成元数据，并定时上传到 Bilibili。

## 二、核心功能模块实现

### 2.1 任务链处理引擎 (ChainTaskHandler)

**文件位置**: `internal/chain_task/chain_task_handler.go`

#### 2.1.1 功能描述

任务链处理引擎是系统的核心，负责协调和执行视频处理的各个步骤。它支持任务的自动重试、并发控制和状态流转。

#### 2.1.2 核心实现

- **并发控制**: 使用 `sync.Map` 跟踪运行中的任务，防止重复执行。
- **任务编排**: 定义标准化的任务链流程（下载 -> 字幕 -> 翻译 -> 元数据 -> 上传）。
- **生命周期管理**: 结合 `TaskCancelManager` 实现任务的优雅启动和终止。

**关键代码逻辑**:

1. **SetUp()**: 
   - 启动时重置中间状态任务。
   - 轮询数据库获取待处理任务。
   - 通过信号量或 worker pool 限制总并发数。

2. **RunTaskChain()**:
   - 注册取消上下文。
   - 按序执行 `TaskStepWrapper`。
   - 处理步骤结果并更新数据库状态。

3. **状态流转**:
   `001 (待处理)` → `002 (处理中)` → `200 (准备上传)` → `300 (视频已上传)` → `400 (完成)`
   异常状态: `999 (失败)`, `998 (用户取消)`

### 2.2 任务取消机制 (TaskCancelManager)

**文件位置**: `internal/chain_task/task_cancel_manager.go`

#### 2.2.1 功能描述

允许用户在前端删除视频或手动停止时，立即终止后端正在执行的长耗时任务（如视频下载、FFmpeg 转码），释放系统资源。

#### 2.2.2 实现细节

- **Context 管理**: 使用 `context.Context` 和 `context.CancelFunc` 管理任务生命周期。
- **唯一标识**: 使用 `savedVideo.ID` (数据库主键) 作为 Context 的 Key，避免 VideoID 可能存在的冲突。
- **外部进程控制**: 对于 `yt-dlp` 和 `aria2c` 等外部命令，统一使用 `exec.CommandContext`。当 Context 取消时，Go 运行时会向子进程发送 `SIGKILL` 信号。

**取消流程**:
1. **任务注册**: 任务开始前调用 `Register(id)`，创建并存储 `CancelFunc`。
2. **信号传递**: 将 Context 注入到任务链 (`context["__ctx__"]`)，并传递给每个具体的 Task Handler。
3. **触发取消**: API 收到删除请求 -> 调用 `Cancel(id)` -> 执行 `CancelFunc` -> Context 关闭 -> 所有监听 `ctx.Done()` 的 Goroutine 退出。
4. **资源回收**: 任务结束（无论成功失败或取消）调用 `Deregister(id)` 清理 Context Map。

### 2.3 上传调度器 (UploadScheduler)

**文件位置**: `internal/chain_task/upload_scheduler.go`

#### 2.3.1 功能描述

负责定时上传视频和字幕到 Bilibili，采用智能调度策略避免频繁上传被平台限制。

#### 2.3.2 调度策略

| 任务类型 | 调度间隔 | 策略说明 |
| :--- | :--- | :--- |
| **视频上传** | 1 小时/个 | 控制上传频率，避免账号风控。 |
| **字幕上传** | 滞后 1 小时 | 确保视频转码和审核通过后再追加字幕，提高成功率。 |

**取消支持**: 在执行上传动作前，会检查 `TaskCancelManager.IsCanceled()`，防止已删除的视频被错误上传。

### 2.4 下载与元数据获取 (DownloadVideo & Metadata)

**文件位置**: `internal/chain_task/handlers/down_load_video.go`

#### 2.4.1 增强型下载

- **多策略重试**: 内置 6 种下载策略组合（代理/无代理 + Cookies/Browser/无Cookies），自动降级尝试。
- **进度追踪**: 解析 `yt-dlp` 和 `aria2c` 的标准输出，实时计算进度并更新数据库。
- **断点续传**: 智能识别 `.part` 文件，支持中断后恢复。

#### 2.4.2 元数据生成

- **AI 分析**: 集成 Gemini 1.5 Pro/Flash 进行多模态视频内容分析。
- **智能摘要**: 自动生成符合 B 站风格的标题、简介和标签。

## 三、AI 服务集成实现

### 3.1 AI 服务管理器 (AIServiceManager)

**文件位置**: `internal/core/services/ai_service_manager.go`

#### 3.1.1 统一接口设计

抽象 `AIProvider` 接口，屏蔽不同厂商 API 差异。支持的后端包括：
- **OpenAI Compatible**: 通用接口，适配 DeepSeek, 通义千问, ChatGPT 等。
- **Gemini Native**: Google 原生 SDK，支持多模态（视频/图片）输入。

#### 3.1.2 故障转移与负载均衡

- **Key 轮询**: Gemini 客户端支持配置多个 API Key，请求时自动轮询，提高配额利用率。
- **自动降级**: 首选 AI 服务失败时，自动尝试备选服务（如 Gemini 失败 -> 尝试 DeepSeek）。

## 四、前端与 API 实现

### 4.1 前后端分离与融合

- **前端架构**: Next.js 15 (React Server Components) 提供现代化 UI。
- **构建融合**: 前端 `npm run build` 生成静态资源 (`out/`)，通过 Go 的 `embed` 特性打包进单一二进制文件。
- **路由代理**: Go Gin 服务器拦截 `/api` 请求处理业务，其他请求 serve 静态文件或 fallback 到 `index.html` (SPA 模式)。

### 4.2 认证与安全

- **B 站扫码登录**: 实现 Bilibili Passport 二维码登录流程，持久化 Cookie 到本地文件。
- **API 安全**: 可扩展的中间件设计，支持 JWT 或 API Key 认证（预留）。

## 五、数据库设计

### 5.1 核心表结构

#### cw_saved_videos (视频主表)
存储视频的基础信息、处理状态和 AI 生成内容。
- `status`: 关键字段，控制任务流转。
- `subtitles`: 存储原始字幕 JSON。

#### cw_task_steps (任务步骤表)
记录每个视频处理步骤的详细历史，用于调试和进度展示。
- `step_name`: 步骤名 (如 "下载视频", "翻译字幕")。
- `status`: execution status (pending/running/completed/failed)。
- `error_msg`: 详细错误日志。

## 六、部署与运维

### 6.1 部署方式

- **单文件部署**: 编译输出的 `ytb2bili` (Windows .exe / Linux binary) 包含所有依赖。
- **依赖工具**: 运行时需依赖 `ffmpeg` 和 `yt-dlp`（系统会自动检测或提示安装）。
- **Docker**: 提供 Dockerfile 支持容器化部署。

### 6.2 配置管理

使用 `config.toml` 进行集中配置，支持热加载（部分配置）和环境变量覆盖。
